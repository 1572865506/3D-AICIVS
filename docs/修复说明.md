## 接口与兼容性变化

- `POST /api/v1/loading/jobs` 返回 HTTP 202 和 job_id。
- `GET /api/v1/loading/{id}/status` 返回 QUEUED/RUNNING/COMPLETED/FAILED/CANCELLED/TIMED_OUT。
- `GET /api/v1/loading/{id}`：运行中返回 202；有结果则返回布局；失败且无结果返回 409。
- `POST /api/v1/loading/{id}/cancel` 请求取消；客户端随后轮询终态。
- `/api/v2/pack` 保留同步响应形式，但实际计算也通过有界子进程执行。
- 未指定 V2 的旧版 `/api/v1/pack` 返回 410；防止绕过新的隔离和验证路径。
- `layout_status` 区分 VALID/INVALID/NOT_EVALUATED；`sequence_status` 区分 FEASIBLE/INFEASIBLE/NOT_EVALUATED。
- `fulfillment_status` 区分 COMPLETE/PARTIAL；计算完成不能代表全部装完。
- `executable` 仅在布局与顺序检查均通过时为真。动画/执行方案导出不再接受缺失验证的旧响应。
- `flatness` 中未计算的值为 null，不再伪装为零缺陷。
- 测试演示模式只能预览，不把演示数据当作可执行方案。
- 核心求解为确定性算法，目前只支持 seed=42；其他种子明确报错。
- 任务保存在内存中，不跨重启持久化。默认 2 个工作进程、8 个待完成任务、128 条记录、终态 TTL 600 秒；HTTP 请求线程上限 32。
- 请求体上限 2 MiB，最多 500 种 SKU、100000 箱。预算范围 (0,300] 秒。
- 默认仅监听 127.0.0.1。跨源访问需显式配置 AICIVS_ALLOWED_ORIGINS；不再允许任意来源。

## 模型边界

载荷传递采用静态均布载荷、按实际接触面积归一化分摊，并保证总重量守恒。压强沿用平均顶面压强定义，不等同于真实包装局部应力。偏心载荷、柔性变形、接触刚度与动态运输条件仍需独立工程验证。

顺序验证仅针对人工逐箱、沿 -X 直线入柜、零额外净空模型，不支持倾斜插入、吊装或临时支架。默认顺序验证预算 2 秒；较大布局可能返回 NOT_EVALUATED，此时只允许预览。不能把该状态升级为可执行。

Python 库预算是协作式软预算，单个不可中断计算片段可能略超时；HTTP 层使用进程边界执行硬超时。中断搜索只能返回经独立验证的候选，不能直接发布半成品。
